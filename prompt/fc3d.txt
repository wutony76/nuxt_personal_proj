# FC3D  福彩3D新增

## 0. 命名慣例

「fc3d」開頭是英文字母，可以直接當 JS/TS 常數／型別／函式名稱前綴，不需要另外取代稱。

大小寫慣例比照 `SSC`（時時彩，玩法結構最接近的先例）：
- 常數：`FC3D_xxx`
- 型別／函式：`Fc3dXxx` / `fc3dXxx`
- composable：`useFc3d`
- 檔名比照 `ssc.ts` / `ssc-of.ts` / `sscof/plays.js`：`fc3d.ts`、`fc3d-of.ts`、`fc3dof/plays.js`

## 1. Project Structure

福彩3D**只有官方盤玩法結構（固定賠率：定位膽／直選／組選／不定位／大小單雙），沒有信用盤**
（bglottery 來源 `fc3d/` 資料夾裡只有 `official/`，沒有 `creditTraditional/`——
`index_script.js` 也證實只呼叫過 `playTabMode: 1`（官方），從沒呼叫過 `2`（信用））。

這跟 11x5／ssc／pk10／k3／x5 的「雙盤口」不同，也跟 kl8／kl10／pceggs 的「信用盤單盤口」不同：
**fc3d 是「官方盤單盤口」**——目前專案裡沒有這個形狀的先例，需要組合兩套既有架構：

- 盤口內部的玩法判定／賠率／複式展開：比照 **SSC-OF**（`shared/config/ssc-of.ts` / `sscof.ts` /
  `sscof/plays.js` / `sscof/helpers.ts`），只是位數從 5 位（萬/千/百/十/個）縮減成 3 位（百/十/個），
  因此沒有「五星」這個分類，fc3d 的「三星」等同 SSC 的「後三」。
- 單一盤口不需要三檔切分（不用 xxxShared/xxxCd/xxxOf）：比照 **EGGS**（PC蛋蛋）的檔案佈局
  （`eggs.ts` / `useEggs.ts` / `egg.vue`）。

-shared/config
├── fc3d.ts            共用（開獎號解析、位數/號碼範圍等純函式），比照 `ssc.ts`
├── fc3d-of.ts         玩法判定與賠率核心（定位膽/前二/後二/三星 直選組選和值/不定位/大小單雙），
│                       比照 `ssc-of.ts`
└── fc3dof/
    ├── plays.js         注項設定（.js，禁止 import，比照 `sscof/plays.js`）
    └── helpers.ts       比照 `sscof/helpers.ts`

-server/services/game/lottery/bg
└── fc3d.ts            單一盤口邏輯，比照 `eggs.ts`（不需要 xxxShared/xxxCd/xxxOf 三檔切分；
                        內部判定/複式展開邏輯可抄 `sscOf.ts` 的寫法，但期別/開獎不必等 CD 交件）

-server/api/lottery
└── fc3d/                current.get.ts / claim.post.ts / opencode-history.get.ts / user-record.get.ts
                          （是否需要 `jackpot.get.ts` 見第 6 節，**預設先不建**）

-app/composables
└── useFc3d.ts         比照 `useEggs.ts`

-app/components/lottery/bg/fc3d/
├── base/              Board（百/十/個位選號盤、複式/單式切換），比照 `ssc/of/base/Board.vue`
└── block/             Header、Report、History、Road、Dialog*、footer/Auto、footer/Chat
                        （比照 `ssc/of/block`／`eggs/block`）

-app/pages/lottery/bg/
└── fc3d.vue           下注頁，比照 `egg.vue` 單頁（不需要拆 cd/of 兩頁）

UI layout 佈局：整體頁面骨架（單頁、無 cd/of 切換）參考 EGGS；
下注看板（三層選單 + 選號盤 + 複式展開 + 大小單雙）參考 SSC-OF。

## 5. Constraints

- 官方盤玩法判定／賠率／複式展開優先複用 SSC-OF 架構，單一盤口的檔案佈局優先複用 EGGS 架構
- 優先複用既有 lottery config pattern
- 不要重新設計整套玩法架構
- 不要自行猜測 fc3d 規則，尤其：
  - `config_ssc.js` 裡 181121113／181121114（組選和值組三/組六）目前是空設定，不可自行編造內容
  - `official/play_script.js` 的 `isrx`／`TSH3` 死代碼分支不可照抄
  - 彩池是否適用（見第 6 節）不可自行假設
- 修改前先閱讀既有實作（特別是 SSC 全套：composable／server／config 三層，以及 EGGS 的單盤口佈局）
- 非 trivial 需求需走 OpenSpec 流程（proposal → design → tasks），此為新彩種、跨多層變更，
  動工前應先建立 `openspec/changes/add-fc3d/` 提案

## 6. 彩池機制（Jackpot）—— 預設不建，需先拍板

與 kl8／kl10／pceggs（信用盤單盤口）不同，fc3d **沒有信用盤可以用 rake 建立彩池**，
bglottery 來源本身也完全沒有彩池相關的欄位或 UI 痕跡（`config_ssc.js`／`official/**` 都是純固定賠率結構）。

專案裡唯一「官方盤玩法接彩池」的先例是 SSC-OF 的「後三直選」與 PK10-OF 的「前三直選」
（見 `shared/config/ssc-of.ts` 檔頭註解），但那兩個先例的資金來源都是**同一彩種的信用盤 rake**
（`SSC_JACKPOT_SETTINGS` 定義在 `ssc-cd.ts`，OF 只是借用同一顆池子），fc3d 沒有信用盤兄弟盤可借，
不能直接套用。

**預設先不做彩池**（`server/api/lottery/fc3d/` 不建 `jackpot.get.ts`），除非需求方明確要求，
且要求時必須先拍板以下決策，不可自行假設：

1. **資金來源**：從三星直選（或哪個玩法）自己抽水建池？還是全部玩法統一抽水？
2. **機制選擇**：是否要比照 SSC-OF「後三直選」的做法，把「三星直選」／「三星直選單式」接上
   分層中獎（`SSC_OF_PRIZE_TIERS` / `sscOfMatchCount` 那套「猜中幾位」分層邏輯），
   還是要用一般的 `buildJackpotShares` 權重池（`shared/config/jackpot.ts`）？這兩套機制職責不同，
   不能混用。
3. **weight 分級與觸發機率窮舉**：同其他彩種，需針對 fc3d 各注項理論賠率重新核對，不可沿用 SSC/PK10 的數字。

在拍板之前，fc3d 所有玩法一律維持 bglottery 來源本來就有的固定賠率結構。
