# KL8  快樂8新增

## 0. 命名慣例

「kl8」開頭是英文字母，可以直接當 JS/TS 常數／型別／函式名稱前綴，
不需要像「11x5」→`X5`、「6hc」→`LHC` 那樣另外取代稱。

大小寫慣例比照 `EGGS`（PC蛋蛋，同為單一盤口彩種）：
- 常數：`KL8_xxx`
- 型別／函式：`Kl8Xxx` / `kl8Xxx`
- composable：`useKl8`
- 檔名：`kl8.ts`、`kl8-cd.ts`、`kl8cd/plays.js`（比照 `eggs.ts` / `eggs-cd.ts` / `eggscd/plays.js`）

## 6. 彩池機制（Jackpot）

需求原文：「增加支援彩池機制，彩池相關設定需要與玩法保持正確關聯」。

kl8 只有一個盤口（無 CD/OF 之分，整個彩種本身即等同信用盤），比照既有慣例，
單一盤口彩種比照 EGGS（PC蛋蛋）接彩池的做法。

**不是新發明一套彩池，是接上專案既有的泛用爆池骨架**（`shared/config/jackpot.ts`），
完整參考案例見 `openspec/reference/eggs-jackpot-plan.md`（PC蛋蛋接彩池的完整記錄：
決策過程、檔案改動清單、驗證清單）。kl8 接彩池的做法與 eggs 幾乎是同一套
（同為單一盤口、單一結算入口，不需要 `k3Shared.ts` 那種「等多盤口交件才結算」的編排），
只是彩種判定與觸發條件要重新分析。

### 6.1 既有架構（直接複用，勿重造）

| 層 | 檔案 | 職責 |
|---|---|---|
| 泛用核心 | `shared/config/jackpot.ts` | `JackpotSettings` / `JackpotRow` / `JackpotHitRecord` 型別 + `buildJackpotShares()` 純函式 |
| 彩種判定 | `shared/config/kl8-cd.ts` | 新增 `KL8_JACKPOT_SETTINGS`／`kl8JackpotHit()`／`kl8JackpotLabel()`（比照 `eggs-cd.ts` 的 `EGGS_...`） |
| 看板設定 | `shared/config/kl8cd/plays.js` + `helpers.ts` | 注項宣告 `weight`（group 層預設＋item 層覆寫）；`helpers.ts` 補 `kl8JackpotWeightOf()` |

金流兩條獨立的線（比照 `eggs.ts`）：

```
下注  playBets()          → issueJackpotMap[issue] += amount * rakeRatio
開獎  settleIssuePrize()  → pool = issueJackpotMap[issue] + carryJackpot
                          → triggered ? 發 pool * payoutRatio : 全部滾存
                          → carryJackpot = jackpot.remain；issueJackpotMap[issue] = 0
```

### 6.2 需要拍板的決策（不可自行假設，動工前先確認）

1. **爆池觸發條件**：既有彩種的判準是「看板上真的押得到、機率與 6hc-cd 特別號開 49（≈2%）同量級」。
   kl8 目前只有任選／兩面兩種玩法，**沒有** eggs／k3／ssc 那種現成的「豹子」圖案概念，
   也沒有 kl10 的龍虎鬥／正和可用，需要重新從機率窮舉候選
   （例如任選「七中七」——20 個開獎號中選 7 個全中，母數與機率都跟 kl10 的「任五中五」不同，
   需另外精算；或兩面裡的極端組合），
   不可比照 eggs 決策直接套用「豹子」，也不可比照 kl10／11x5 決策套用「全5中1」或「任五中五」。
2. **weight 分級**：沿用 6hc 的理論賠率分級法（`1/命中機率` ≥20→3、2.5~20→2、<2.5→1），
   逐項對照 kl8-CD 各注項理論賠率標核對；兩面（和值/上下盤/奇偶盤/五行）的機率須先查證判定規則
   （見上方 Step 1 對 `liangmian/play_script.js` 的註記）才能精算，不可憑空假設。

### 6.3 關聯機制（需求核心，務必落實）

- 設定檔宣告 weight（group 層預設 + item 層覆寫）
- 注單需存 `playKey` + `tabId` + `betCode` + `odds`（既有 `orders.ts` 已支援，不需改）
- 結算時用 `(playKey, tabId, betCode)` 反查 weight，解析順序 `item.weight → group.weight → 0`
  ⚠️ **明確 `weight: 0`（排除在彩池外）與「完全沒設定」（退回 `weightFallback`）是兩件不同的事**，
  必須用 `== null` 判斷，不可用 falsy 判斷（此語意在 `shared/config/jackpot.ts` 也要守一次）

### 6.4 頭獎機制（KL8 必做，與 KL10／EGGS 對齊）

KL8 需明確具備「頭獎」分層，不可只有抽水與滾存。

- 以 `shared/config/kl8-cd.ts` 定義 KL8 的 jackpot 分層時，需包含 `name: '頭獎'` 的 pool layer
- 該層需有明確：
  - `ratio`（派發占比）
  - `minAmount`（頭獎最低保障）
- 觸發語意與 KL10/EGGS 一致：
  - 只有在 `kl8JackpotHit()` 命中時才會進入派發
  - 未觸發期不得派發頭獎，池子全額滾存
- 流程要求：
  - 下注階段：累積至 `issueJackpotMap`
  - 開獎階段：`pool = issueJackpotMap[issue] + carryJackpot`
  - 觸發後：依分層（含頭獎）配比派發
  - 未觸發／不足門檻：寫回 `carryJackpot`
