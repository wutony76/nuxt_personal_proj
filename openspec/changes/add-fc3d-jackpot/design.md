## Context

FC3D 上線時依規範「預設不建彩池」，`shared/config/fc3d-of.ts`／`fc3d.ts` 頭部註解明確寫著
「fc3d 只有官方盤、沒有彩池，故本檔不含任何 pool/jackpot 分支」。使用者現在明確要求把彩池機制
「完善」成跟 PL3 一樣。

**PL3（排列3）就是本次的直接先例**，不必再重新比照 SSC-OF／EGGS 從零設計：FC3D 與 PL3 是本專案
裡結構完全相同的兩個彩種（皆為官方盤單盤口、無信用盤、3 位 0~9 可重複開獎、玩法/分頁/複式展開
規則逐字相同，唯一差異只有頁面文案與 tabId 前綴 18 vs 19），PL3 稍早已完成同一套彩池機制
（見 `openspec/changes/add-pl3-jackpot/`），機制、數值、判定方式全部直接複用，不重新設計。

## Goals / Non-Goals

**Goals:**
- 三星直選複式／單式改吃分層彩池，賠率不再固定（依命中位數 0~3 分層），數值完全比照 PL3。
- 全站爆池：所有分頁下注一律抽水參與，開出豹子觸發，依權重分潤，數值完全比照 PL3。
- 兩個池各自獨立記帳（池底／抽水／滾存互不影響）。
- 資金來源比照 PL3／SSC-OF／EGGS 慣例：對整筆送單金額抽水，不篩選分頁。

**Non-Goals:**
- 不引入跨 class 單例（FC3D 只有一個盤口，不需要 `fc3dShared.ts`）。
- 不改動三星直選以外的其他 9 個分頁的固定賠率判定邏輯。
- 不影響 PL3／SSC／PK10／EGGS 既有彩池。
- 不重新設計機率或分層比例、不重新拍板抽水／池底數值——直接沿用 PL3 的既有實作。

## Decisions

### 1. 機制與數值 100% 比照 PL3（唯一差異是命名空間 Pl3→Fc3d／PL3→FC3D）

因為 FC3D 與 PL3 判定核心（`fc3d-of.ts` vs `pl3-of.ts`）在加彩池之前就已經是逐字相同的結構
（僅注碼前綴文案與 import 路徑不同），本次採「以 PL3 目前的原始碼為底稿，做識別字替換」的方式
產生 FC3D 版本，而非重新從 EGGS/SSC-OF 推導一次。實測比對 `pl3-of.ts`／`pl3.ts` 做過
`PL3→FC3D`／`Pl3→Fc3d`／`pl3→fc3d` 替換後，與現有 `fc3d-of.ts`／`fc3d.ts`（加彩池前）逐行比對，
非彩池段落 100% 一致，證實這個轉換是安全的。

| 項目 | 數值（與 PL3 相同） |
|---|---|
| 三星直選命中3（頭獎） | 彩池 × 70%，保底 20,000 |
| 三星直選命中2（二獎） | 彩池 × 20%，無保底 |
| 三星直選命中1（三獎） | 固定 2 倍下注額 |
| 三星直選池抽水比例 | 60%（對整筆送單金額） |
| 三星直選池底範圍 | 120,000 ~ 480,000 |
| 全站爆池觸發 | 開出豹子（三位數字全同），機率 1% |
| 全站爆池抽水比例 | 1%（對整筆送單金額） |
| 全站爆池可派發比例 | 50% |
| 全站爆池池底範圍 | 110,000 ~ 450,000 |

判定方式（逐位比對，非集合交集）、未中獎分層整塊滾存、三星直選注單同時參與兩池等規則，
全部與 PL3 相同，詳見 `openspec/changes/add-pl3-jackpot/design.md` 決策 1~5（不重複展開）。

### 2. tabId 沿用 FC3D 自己的既有編號（181121010／181121011），不是 PL3 的 191121010／191121011

FC3D 的分頁 id 沿用來源 `bglottery fc3d/config_ssc.js` 的 playId（18 開頭），與 PL3 的 19 開頭
是各自獨立的編號空間，本次只在既有的 `181121010`（三星直選複式）／`181121011`（三星直選單式）
的 `combo` 上加 `pool: true`，不改動任何 tabId。

## Risks / Trade-offs

- **[Risk]** 對整筆送單金額抽水（非僅三星直選自身）意味著玩家下注其他分頁時，資金也會被
  高比例（60%）撥入三星直選池，而該分頁仍按原固定賠率由「house」支付。
  → **Mitigation**：與 PL3／SSC-OF／EGGS 既有真實行為一致（非本次新增瑕疵），已有先例。
- **[Risk]** 三星直選改浮動賠率後，玩家原本看到的固定 960.00 賠率消失。
  → **Mitigation**：前端顯示「浮動賠率（依彩池分潤）」並顯示即時可派發彩池／保底金額，
  版面完全比照 PL3 的既有呈現方式。
- **[Risk]** 兩個池互相污染（例如誤用同一個 `carry` 欄位或誤把三星直選注單漏算進全站爆池）。
  → **Mitigation**：欄位／函式命名與 PL3 逐字對應（`issueJackpotMap` vs `issuePoolMap`、
  `carryJackpot` vs `carryPool`），且是直接複製 PL3 已驗證過的邏輯，非重新手刻。

## Migration Plan

FC3D 沒有既有彩池下注歷史需相容（三星直選本來就是固定賠率）。實作順序：
1. `shared/config/fc3d-of.ts`（以 pl3-of.ts 為底做識別字轉換 + 補回 fc3d 專屬頭部註解）
2. `shared/config/fc3dof/plays.js`／`fc3dof/helpers.ts`（`pool: true` 標記、
   `fc3dOfIsPoolTab`／`fc3dJackpotWeightOf`）
3. `server/services/game/lottery/bg/fc3d.ts`（記帳與結算，同樣以 pl3.ts 為底轉換）
4. 2 支新 API（`jackpot.get.ts`／`pool.get.ts`）
5. 前端（`api.ts`／`useFc3d.ts`／元件顯示）
6. 端到端驗證：下注三星直選 + 其他分頁各一筆 → 確認兩個池都正確累積 → 等開獎 →
   確認分層派彩與爆池分潤皆正確、未中獎分層正確滾存
