# PL3  排列3新增

## 0. 命名慣例

「pl3」開頭是英文字母，可以直接當 JS/TS 常數／型別／函式名稱前綴，不需要另外取代稱。

大小寫慣例比照 `SSC`（時時彩，玩法結構最接近的先例）：
- 常數：`PL3_xxx`
- 型別／函式：`Pl3Xxx` / `pl3xxx`
- composable：`usePl3`
- 檔名比照 `ssc.ts` / `ssc-of.ts` / `sscof/plays.js`：`pl3.ts`、`pl3-of.ts`、`pl3of/plays.js`

## 1. Project Structure

排列3**只有官方盤玩法結構（固定賠率：定位膽／直選／組選／不定位／大小單雙），沒有信用盤**
（bglottery 來源 `pl3/` 資料夾裡只有 `official/`，沒有 `creditTraditional/`——
`index_script.js` 也證實只呼叫過 `playTabMode: 1`（官方），從沒呼叫過 `2`（信用））。

這跟 11x5／ssc／pk10／k3／x5 的「雙盤口」不同，也跟 kl8／kl10／pceggs 的「信用盤單盤口」不同：
**pl3 是「官方盤單盤口」**——跟 FC3D（福彩3D）是同一種形狀，實作方式幾乎一致，需要組合兩套既有架構：

- 盤口內部的玩法判定／賠率／複式展開：比照 **SSC-OF**（`shared/config/ssc-of.ts` / `sscof.ts` /
  `sscof/plays.js` / `sscof/helpers.ts`），只是位數從 5 位（萬/千/百/十/個）縮減成 3 位（百/十/個），
  因此沒有「五星」這個分類，pl3 的「三星」等同 SSC 的「後三」。
- 單一盤口不需要三檔切分（不用 xxxShared/xxxCd/xxxOf）：比照 **EGGS**（PC蛋蛋）的檔案佈局
  （`eggs.ts` / `useEggs.ts` / `egg.vue`）。

-shared/config
├── pl3.ts             共用（開獎號解析、位數/號碼範圍等純函式），比照 `ssc.ts`
├── pl3-of.ts          玩法判定與賠率核心（定位膽/前二/後二/三星 直選組選和值/不定位/大小單雙），

-server/api/lottery
└── pl3/                 current.get.ts / claim.post.ts / opencode-history.get.ts / user-record.get.ts
                          （是否需要 `jackpot.get.ts` 見第 6 節，**預設先不建**）

-app/composables

## 5. Constraints

- 官方盤玩法判定／賠率／複式展開優先複用 SSC-OF 架構，單一盤口的檔案佈局優先複用 EGGS 架構
- 優先複用既有 lottery config pattern
- 不要重新設計整套玩法架構
- 不要自行猜測 pl3 規則，尤其：
  - `config_ssc.js` 裡 191121113／191121114（組選和值組三/組六）目前是空設定，不可自行編造內容
  - 彩池是否適用（見第 6 節）不可自行假設
- 不要把 fc3d 開發時發現的死代碼（`isrx`/`TSH3` 分支）誤植回 pl3，pl3 的來源檔案本身沒有這段
- 修改前先閱讀既有實作（特別是 SSC 全套：composable／server／config 三層，以及 EGGS 的單盤口佈局）
- 非 trivial 需求需走 OpenSpec 流程（proposal → design → tasks），此為新彩種、跨多層變更，
  動工前應先建立 `openspec/changes/add-pl3/` 提案

## 6. 彩池機制（Jackpot）—— 預設不建，需先拍板

與 kl8／kl10／pceggs（信用盤單盤口）不同，pl3 **沒有信用盤可以用 rake 建立彩池**，
bglottery 來源本身也完全沒有彩池相關的欄位或 UI 痕跡（`config_ssc.js`／`official/**` 都是純固定賠率結構）。

專案裡唯一「官方盤玩法接彩池」的先例是 SSC-OF 的「後三直選」與 PK10-OF 的「前三直選」
（見 `shared/config/ssc-of.ts` 檔頭註解），但那兩個先例的資金來源都是**同一彩種的信用盤 rake**
（`SSC_JACKPOT_SETTINGS` 定義在 `ssc-cd.ts`，OF 只是借用同一顆池子），pl3 沒有信用盤兄弟盤可借，
不能直接套用。

**預設先不做彩池**（`server/api/lottery/pl3/` 不建 `jackpot.get.ts`），除非需求方明確要求，
且要求時必須先拍板以下決策，不可自行假設：

1. **資金來源**：從三星直選（或哪個玩法）自己抽水建池？還是全部玩法統一抽水？
2. **機制選擇**：是否要比照 SSC-OF「後三直選」的做法，把「三星直選」／「三星直選單式」接上
   分層中獎（`SSC_OF_PRIZE_TIERS` / `sscOfMatchCount` 那套「猜中幾位」分層邏輯），
   還是要用一般的 `buildJackpotShares` 權重池（`shared/config/jackpot.ts`）？這兩套機制職責不同，
   不能混用。
3. **weight 分級與觸發機率窮舉**：同其他彩種，需針對 pl3 各注項理論賠率重新核對，不可沿用 SSC/PK10/fc3d 的數字
   （即使 fc3d 玩法結構幾乎相同，也要各自重新窮舉，兩個彩種的賠率標不一定一樣）。

在拍板之前，pl3 所有玩法一律維持 bglottery 來源本來就有的固定賠率結構。
